# Как устроен движок

Прототип состоит из двух файлов: [`../extract.js`](../extract.js) (117 строк)
снимает геометрию в браузере, [`../build_pptx.py`](../build_pptx.py) (147 строк)
собирает PPTX. Разделение намеренное: измерение требует движка раскладки
(Chromium), сборка требует python-pptx, смешивать их в одном процессе незачем.

## Конвейер

1. Локальный сервер отдает HTML: `python -m http.server 8777`. Playwright
   грузит страницу по `http://127.0.0.1:8777/...`.
2. `build_pptx.py` запускает headless Chromium с `device_scale_factor=2`,
   ждет `networkidle`, выполняет `extract.js` через `page.evaluate`.
3. `extract.js` возвращает JSON: по каждому слайду списки `boxes`, `texts`,
   `images`, плюс коэффициент `epx`.
4. Скрипт гасит текст диаграмм и подпись кота инъекцией CSS
   (`visibility:hidden`), затем скриншотит растровые элементы по атрибуту
   `data-cap` в каталог `_imgs/`.
5. python-pptx строит слайды: сначала фигуры, потом картинки, потом текст.
   Порядок задает z-order: заливки внизу, текст поверх.

Результат на реальной презентации: 10 слайдов, 80 фигур, 139 текстовых блоков,
19 картинок, файл 142934 байта. 19 картинок это 15 иконок lucide, 3 диаграммы,
1 кот.

## Единицы и масштаб

Слайд HTML: 1160x653 px (точно 652.5), пропорция 16:9. Слайд PPTX: 12192000 x
6858000 EMU, это 13.333 x 7.5 дюйма.

Коэффициент `epx = 12192000 / 1160 = 10510.34` EMU на пиксель. Один и тот же по
обеим осям: 652.5 * 10510.34 = 6858000, сходится. Все координаты и размеры из
браузера в пикселях умножаются на `epx`.

Кегль шрифта переводится из CSS-пикселей в пункты множителем 0.75 (72/96).
Пример: заголовок 32px становится 24pt.

`device_scale_factor=2` дает растр в двойном разрешении. Иконка 22px
скриншотится как 44px и вставляется на место размером 22px, поэтому не мылит.

## Съем геометрии: extract.js

Обход дерева каждого `section.slide` через `TreeWalker`. Для каждого элемента:

Фигура. Если у элемента непрозрачный фон или видимая граница, пишется `box` с
координатами относительно слайда, заливкой и рамкой. Радиус скругления берется
из `borderTopLeftRadius`. Круг и эллипс распознаются по условию `radius >=
min(w,h)/2` и помечаются `radius:-1`.

Текст. Элемент с прямым непустым текстовым узлом дает `text`. Прямоугольник
текста снимается через `Range.selectNodeContents(el).getBoundingClientRect()`,
это точный ink-бокс с учетом padding, выравнивания и переносов. Шрифт,
начертание, цвет, выравнивание и `letter-spacing` из `getComputedStyle`.
`innerText` отдает текст с учетом `text-transform`, поэтому uppercase не
пересчитывается.

Растровые корни. Три класса элементов не разбираются на фигуры и не обходятся
внутрь: `svg.lucide` (иконки), `svg` с viewBox но без класса lucide (диаграммы),
`.cat-card` (кот). Им ставится атрибут `data-cap`, по нему потом делается
скриншот. Текст внутри диаграмм при этом извлекается отдельно как нативный и
кладется поверх картинки: позиция по `getBoundingClientRect`, выравнивание по
`text-anchor`, кегль по `font-size` умноженному на масштаб рендера SVG.

Левая акцентная полоса слайда это псевдоэлемент `::before`, его в DOM нет.
Он читается через `getComputedStyle(slide, '::before')` и пишется отдельной
фигурой.

## Сборка: build_pptx.py

`add_box` создает автофигуру: `OVAL` при `radius:-1`, `ROUNDED_RECTANGLE` при
положительном радиусе (доля скругления `min(0.5, rad/min(w,h))`), иначе
`RECTANGLE`. Тень по умолчанию у автофигур снимается: `shape.shadow.inherit =
False`. Заливка и рамка из данных; отсутствие рамки это `line.fill.background()`.

Односторонняя граница (левая полоса `.mini`, `.explain`, верхняя полоса карточек
слайда 8) в родную фигуру не ложится: у прямоугольника PPTX рамка только со всех
сторон сразу. Такая граница пишется отдельной тонкой залитой фигурой. Логика в
`extract.js`: если четыре стороны не равны по ширине и цвету, пишется заливка
без рамки плюс по тонкому прямоугольнику на каждую видимую сторону.

`add_text` кладет текстовый блок с нулевыми внутренними полями и вертикальным
центрированием. Перенос строк включается только для реально многострочного
текста: `word_wrap = ("\n" not in text) and (h > size*1.6)`. Причина в
[03-lessons.md](03-lessons.md). Явные переносы (`<br>` дает `\n` в `innerText`)
разбиваются на абзацы. `letter-spacing` кладется в атрибут `spc` (в сотых пункта).

## Запуск

```
python -m http.server 8777 --bind 127.0.0.1   # в каталоге с HTML
python build_pptx.py
```

Результат: `presentation_editable.pptx` рядом со скриптом. Промежуточные
картинки в `_imgs/`.
