# MPGA — презентация из нейросети в PowerPoint

Нейросети отлично делают презентации в HTML и совсем не умеют делать `.pptx`.
MPGA берёт HTML и собирает из него настоящий файл PowerPoint, где **каждый
заголовок, абзац и фигура — обычный объект**, а не картинка: текст выделяется,
правится и переносится.

Ничего устанавливать не нужно. Открывается в браузере, работает без интернета,
файл никуда не отправляется.

Открыть: **https://mpga.kiviuly.ru**

## Как пользоваться

1. Откройте https://mpga.kiviuly.ru — или скачанный `MPGA.html` двойным щелчком.
2. Нажмите **«Скопировать задание для нейросети»** и вставьте его в ChatGPT,
   DeepSeek, GigaChat или Claude, дописав свою тему.
3. Нейросеть пришлёт код. Скачайте его файлом или просто скопируйте из чата.
4. Перетащите файл в окно MPGA (или вставьте код в поле «Нейросеть дала код
   прямо в чате»).
5. Нажмите **«Скачать PowerPoint»**.

Кнопка **«Попробовать на примере»** делает готовую презентацию без всякого
чата — за два щелчка, чтобы сразу увидеть результат.

## Если не получилось

**Скачанный файл открылся как текст, а не как страница.** Правый щелчок по
файлу → «Открыть с помощью» → ваш браузер (Chrome, Edge, Яндекс).

**PowerPoint открыл файл с жёлтой полосой «Защищённый просмотр».** Так Windows
относится ко всему скачанному из интернета. Нажмите «Разрешить редактирование».

**Пропали иконки или картинки.** Значит, нейросеть подключила их по ссылке из
интернета. MPGA подставляет свои иконки, но фотографии по ссылке вставить не
может — попросите нейросеть обойтись иконками и схемами.

**Текст вылез за рамку карточки.** В PowerPoint шрифт чуть шире, чем в браузере.
Потяните рамку за угол или сократите подпись. Чтобы этого не было, просите у
нейросети короткие подписи — так написано в задании.

**Слайды поехали.** Скорее всего, нейросеть проигнорировала размер слайда.
Нажмите «Скопировать замечания для нейросети» под результатом и отправьте их в
тот же чат — придёт исправленный файл.

**Ничего не помогает.** Откройте issue и приложите свой HTML.

## Для разработки

Стек как у соседних проектов: Bun, oxlint, oxfmt.

```
bun install          # puppeteer-core для тестов, линтер и форматтер
bun run icons        # пересобрать набор иконок из lucide-static
bun run build        # собрать dist/: офлайн-файл и сайт (нужно до тестов)
bun test             # прогнать примеры и сверить с рендером LibreOffice
bun run e2e          # проверить собранный файл как пользователь, с обрывом сети
bun run seo          # проверить разметку выдачи на живом сайте
bun run og           # перерисовать картинку для ссылок
bun run lint         # oxlint
bun run format       # oxfmt
bun run convert -- deck.html -o deck.pptx   # пакетная конвертация без браузера
bun run dev          # поднять страницу локально на :3000
```

Проверка результата требует LibreOffice (`soffice`), `pdftoppm` и ImageMagick.
Тесты открывают собранный файл в headless-браузере, обрывают все сетевые
запросы и сверяют PPTX с тем, как та же презентация выглядит в браузере.

## Как это развёрнуто

Сервис живёт в общем стеке `kiviuly`: свой контейнер на Bun отдаёт одну
статическую страницу, наружу её публикует Caddy по HTTPS.

```
docker compose up -d mpga          # из /root, где лежит общий compose
docker compose logs -f mpga
```

| Что | Где |
| --- | --- |
| [`Dockerfile`](Dockerfile) | двухступенчатый: первая собирает сайт из исходников, вторая только отдаёт |
| [`server/main.ts`](server/main.ts) | сервер на Bun: файлы в памяти, ETag, вечный кеш для сборок с хешем в имени |
| [`compose.yml`](compose.yml) | описание сервиса; порт по умолчанию 7200 |
| [`compose.caddy.yml`](compose.caddy.yml) | оверрайд: порт уезжает на localhost, наружу отдаёт Caddy |

Домен задаётся переменной `MPGA_DOMAIN` в `/root/.env`, блок сайта — в
`/root/Caddyfile`.

Сборка даёт два разных выхода из одних исходников:

- `dist/MPGA.html` — один файл со всем внутри. Это то, что скачивается кнопкой
  «Сохранить страницу себе» и работает с диска без интернета.
Каталог `dist/` в репозиторий не попадает: его собирает образ при сборке, а
локально — `bun run build`. Иначе каждая локальная сборка помечала бы рабочую
копию на сервере изменённой, и автообновление отказывалось бы работать.

- `dist/site/` — то, что отдаётся по адресу: лёгкая страница (11 КБ по сети),
  движок отдельным файлом с хешем в имени, инструкция, `robots.txt`,
  `sitemap.xml` и картинка для ссылок в мессенджерах.

Движок подгружается, когда человек впервые собирает презентацию, и тихо
догружается в простое — чтобы страница, открытая заранее, работала и без сети.

## Автообновление

Сервер сам забирает новые коммиты и пересобирает сервис. Наружу при этом ничего
не открывается и никаких ключей от сервера на GitHub не лежит: сервер ходит за
изменениями сам, а не принимает команды извне.

```
sudo deploy/install.sh
```

| Что нужно | Команда |
| --- | --- |
| выключить | `systemctl disable --now mpga-update.timer` |
| включить обратно | `systemctl enable --now mpga-update.timer` |
| обновить прямо сейчас | `systemctl start mpga-update.service` |
| посмотреть, что происходит | `journalctl -u mpga-update.service -f` |
| когда следующая проверка | `systemctl list-timers mpga-update.timer` |

Установщик кладёт исполняемую копию скрипта в `/usr/local/sbin/mpga-update`, а
не запускает его из репозитория: иначе откат на коммит, где этого файла ещё не
было, оставил бы systemd без исполняемого файла. После правки
`deploy/update.sh` установку нужно повторить.

Настройки — в `/etc/default/mpga-update`: ветка, интервал, адрес проверки
здоровья и обязательность подписи коммитов. Интервал меняется в
`/etc/systemd/system/mpga-update.timer` (по умолчанию — раз в две минуты).

Что делает обновление безопасным:

- **Только вперёд по одной ветке.** `git merge --ff-only`; если ветку
  переписали, обновление останавливается и просит посмотреть руками.
- **Чужие правки не затираются.** Если в рабочем каталоге на сервере есть
  несохранённые изменения, обновление не начнётся.
- **Репозиторий проверяется.** Если `origin` вдруг указывает не на тот адрес,
  обновление останавливается.
- **Неудачная сборка ничего не роняет.** Docker подменяет контейнер только
  после успешной сборки, старый продолжает работать.
- **Проверка после запуска.** Новая версия должна ответить на `/health`;
  если не отвечает — автоматический откат на предыдущий коммит.
- **Подпись коммитов.** `REQUIRE_SIGNED=1` в настройках заставит принимать
  только подписанные коммиты.

Чего этот механизм не делает: он не защищает от того, кто может писать в саму
ветку. Тот, кто пушит код, выполняет его на сервере — это верно для любого
автодеплоя.
